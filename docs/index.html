See this docker container?

Set up by hand a while ago. Nobody wrote down how.

I wish I could run another one just like it…

But look at all these settings! 😱 How can I turn this into a docker run command?

That is what runlike does.

Give it a container and it prints the docker run command that recreates it, every pesky option included: ports, volumes, networks, limits, labels, the lot.

Download, rename to runlike, make it executable, put it on your PATH. On macOS and Linux:

curl -fsSLo runlike https://github.com/lavie/runlike/releases/latest/download/runlike-linux-amd64
chmod +x runlike && sudo mv runlike /usr/local/bin/

Downloading with curl also sidesteps macOS's quarantine prompt for unsigned binaries.

Go 1.24 or later. Lands in $(go env GOPATH)/bin.

go install github.com/lavie/runlike/v2/cmd/runlike@latest

assaflavie/runlike ships runlike with the Docker CLI. Mount the socket:

docker run --rm -v /var/run/docker.sock:/var/run/docker.sock assaflavie/runlike CONTAINER

Or make it an alias:

alias runlike="docker run --rm -v /var/run/docker.sock:/var/run/docker.sock assaflavie/runlike"

Usage

Point it at a container. Read the line, edit it, run it.

runlike web
Prints the docker run command for the container web, on one line, every value quoted for the shell.
eval "$(runlike --no-name web)"
Run the copy. Why eval? A bare $(runlike web) makes the shell split the output on spaces and keep the quotes as text, so GREETING=hello world reaches Docker as two broken arguments. eval parses the line the way it would if you typed it.
runlike -p web
Pretty. One option per line, as in the example above. Easier to read, and to delete the one line you want to change.
docker inspect web | runlike --stdin
From saved JSON. No daemon needed: paste inspect output from a ticket, a backup or another machine. Without image data runlike prints a bit more than it has to (see caveats).
--no-name
Leaves out --name, so the copy does not collide with the original. Use it whenever the original is still running.
--no-labels or -l
Leaves out --label. Handy for containers that Compose or an orchestrator covered in metadata.
--use-volume-id
Keeps the generated names of anonymous volumes, so the copy reuses their data instead of starting with fresh ones.
--shell powershell or --shell cmd
Quotes for PowerShell 7.3 or later, or for cmd.exe, instead of a POSIX shell. Paste the line; no eval there.

About those warnings

When something cannot be recreated exactly, runlike still prints the command, and adds a line starting with runlike: warning: on stderr that says what is off and what to do about it. Warnings never land in the command, so eval "$(runlike X)" keeps working. Typical ones: the image tag now points at a different image, a network setting needs a docker network connect after the fact, or a MAC address on a further network could not be told apart from a random one.

Caveats

A few things can't be copied exactly: Docker doesn't keep them, or docker run has no flag for them. Here is what to watch for.

  • Seccomp profiles are stored as JSON, not as the file name you passed. runlike prints the JSON; save it to a file and pass that instead.
  • Exec-form health checks from a Dockerfile (HEALTHCHECK CMD ["curl", …]) have no docker run flag. They come back as --health-cmd, which runs through /bin/sh.
  • -e NAME without a value copies NAME from your environment when you run the line, which may differ from the original's empty value.
  • The same variable set twice: only the last counts; runlike prints both.
  • MAC addresses on further networks: Docker reports a pinned MAC only for the first network. On others, runlike prints none, so a copy never duplicates a random one. If you pinned it, add mac-address= to that --network yourself.
  • Upper case on extra networks is lowercased by docker run itself in the long --network=name=… form.
  • --stdin mode has no image and no daemon to ask: values the image already sets are printed too, container: targets come out as IDs, and only Docker's built-in defaults are left out.
  • Hyper-V isolation on Windows is tested on saved inspect data only.
  • Client-only options such as --pull, --quiet, --detach-keys and --sig-proxy are never stored by Docker, so no tool can read them back.

Contributing

runlike lives at github.com/lavie/runlike. Found a container it gets wrong? Open an issue with the docker inspect output (minus secrets). Pull requests are welcome; every option is checked by a round trip against a real Docker daemon, so bring a test.
